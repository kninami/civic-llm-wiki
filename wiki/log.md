## [2026-09-02] ingest | 우편번호 자동검색 — 파이썬 판

- [[우편번호-자동검색-파이썬]] + 실행 스크립트 `wiki/tools/우편번호채우기.py`
- 목적 — 활동가가 엑셀 파일만 두고 요청하면 LLM이 처리해 돌려주는 방식. 시트를 열고 수식을 채울 필요 없음
- **만들며 실측으로 확인한 것**
  - 네이버는 우편번호를 **서버 HTML에 그대로 실어 보냄** → 브라우저 없이 추출 가능
  - **오탐 발견** — `우편번호` 근처 5자리 숫자를 느슨히 찾으면 블로그 본문의 "(우편번호 12345)" 예시를 집어옴. 존재하지 않는 주소에 `12345`가 나옴. `우편번호</span>NNNNN` / `우편번호 · NNNNN · 복사` 두 **구조를 그대로 요구**하는 방식으로 해결
  - **403 차단** — `User-Agent`만으로는 막힘. `Accept` 헤더가 있어야 통과 (curl이 기본으로 보내던 것)
  - `--개수` 검증 모드가 전체 결과 파일을 덮어쓰던 문제 → `_샘플` 접미사로 분리
- **판단한 것**
  - Apps Script 판과 **별도 도구로 등재.** 같은 목적이지만 사용 방식(시트 수식 vs 파일 처리)과 위험 크기가 달라 한 페이지에 담으면 흐려짐. 서로 링크
  - P4·G3 위험을 Apps Script 판보다 **높게** 서술 — 파일 단위 처리라 한 번에 나가는 주소 양이 훨씬 많음
  - 실패를 빈칸이 아니라 `#못찾음`·`#조회실패`로 표시. Apps Script 판의 조용한 실패 문제를 설계로 막음
  - `status: 시범` — 실제 단체 사용 이력 없음. 수백 건 규모에서 네이버가 차단하는 시점 미확인

## [2026-09-02] ingest | 우편번호 자동검색 도구 (첫 도구 등재)

- [[우편번호-자동검색]] — Google Sheets 맞춤 함수로 네이버 검색을 긁어 우편번호를 채우는 Apps Script
- 개념 2건 신설 — [[웹-스크래핑]] [[API]]
- **판단한 것**
  - `ai_role: AI-미사용`으로 등재. [[guardrails]] G6-③("생성형 AI가 아니어도 처리 가능한 업무는 다른 도구를 우선")이 권하는 방향이며, 이 위키가 비-AI 자동화를 1급으로 다루는 첫 사례
  - **AI를 안 써도 위험이 없지는 않음** — 회원 주소가 검색어로 네이버에 전송됨. 가이드는 생성형 AI 기준이나 "외부로 데이터가 나간다"는 구조는 동일하므로 P4·G3를 확장 적용
  - 주의사항은 13행 전체가 아니라 **해당하는 4개(P1, P4·G3, G1, G4)만** 남김. AGENT.md의 "억지로 채우지 않는다" 적용
  - 이식 전 **공식 API 검토를 권고** — 행정안전부 도로명주소 API가 우편번호를 무료 제공. 깨지지 않고 약관 문제도 없음
  - 코드 분석(선택자 취약성, `substring` 조건, 조용한 실패)은 **분량 문제로 페이지에서 덜어냄**. 핵심만 「사용법 — 막히는 곳」과 「주의사항」에 남김
- **확인 못 한 것** — 제출 단체 / 실제 처리 건수 / 사용 기간 / 지금도 동작하는지. `org: 미상 (확인 필요)`로 두고 [[index]] "아직 없는 것"에 기록
